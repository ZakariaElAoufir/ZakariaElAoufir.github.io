The Wall

Démo Architecture Code

Stack

Application mobile

  • Flutter Material, 8 écrans
  • Dart 3.9 async, Future, Stream
  • image_picker image depuis la galerie
  • intl format des dates

Supabase

  • supabase_flutter 2 client Dart
  • Auth e-mail et mot de passe, session gardée
  • PostgreSQL 6 tables, une fonction SQL
  • Realtime fil et profils en direct
  • Storage chat-pictures, profile-pictures

Outils

  • Android émulateur et téléphone
  • Git et GitHub travail en binôme

Choix techniques

Supabase plutôt qu'une API maison

Pourquoi
Authentification, base, temps réel et fichiers sont fournis : le projet se concentre sur Flutter.
Alternative
Une API Spring Boot devant PostgreSQL.
Compromis
Les règles métier (pas de doublon, amitié dans les deux sens) vivent dans l'application, et la sécurité repose sur les règles RLS.

Amitié écrite dans les deux sens

Pourquoi
Lister ses amis, les compter ou les exclure de « Add Friends » se fait avec un seul filtre sur user_id.
Alternative
Une seule ligne par amitié et un OR sur les deux colonnes.
Compromis
Deux lignes à garder cohérentes, sans transaction côté application.

Images dans Storage, URL en base

Pourquoi
La table messages reste légère ; l'image est servie directement par Supabase depuis son URL publique.
Alternative
Stocker l'image en base, encodée.
Compromis
Deux écritures par envoi, et le fichier reste dans le bucket si le message est supprimé.

Temps réel pour le fil, chargement pour la messagerie

Pourquoi
Le fil et les profils suivent la base avec .stream() ; la messagerie charge à l'ouverture, plus simple à écrire et à tester.
Alternative
Un flux sur messages filtré par conversation.
Compromis
Un message reçu n'apparaît qu'en rouvrant la conversation.

Limites et suites

Limites connues

  • La messagerie n'est pas en temps réel : il faut rouvrir la conversation pour voir un nouveau message.
  • La liste des conversations fait deux requêtes par ami (dernier message, non lus).
  • Supprimer un message laisse son image dans le bucket.
  • Le statut « en ligne » ne repasse à « hors ligne » qu'à la déconnexion ou à la fermeture complète de l'application.
  • Pas encore d'écran pour publier ni pour choisir sa photo de profil ; « Forgot Password? » n'est pas branché.
  • Schéma et règles RLS non versionnés ; dépendances Firebase restées dans le projet sans être utilisées.

Pistes

  • Écouter messages avec .stream() filtré sur la conversation.
  • Une vue SQL qui donne dernier message et non lus en une requête.
  • Accepter une demande dans une fonction SQL, en une transaction.
  • Versionner le schéma et les règles RLS avec les migrations Supabase.
  • Publier depuis l'application, avec photo de profil.
